# MVP PRD：切歌别手滑

## 1. 产品概述

切歌别手滑是一款放在 KTV 手机点歌 H5 入口里的轻量反应/节奏小游戏。

用户在 30-60 秒内面对一连串“副歌点、冷场点、社死歌、全员会唱神曲”等视觉事件，在正确时机点击正确按钮，争取高连击和高准确率。

一句话：

> 副歌快到了，别手滑。30 秒看你是不是包厢遥控器之王。

## 2. 背景与约束

项目背景：

- 入口来自 KTV 手机点歌 H5。
- 用户是混合人群，不应默认女性向。
- 方向要轻量、可快速复制，优先借鉴成熟小游戏机制。
- 不能做成本地生活、重组局、陌生人社交或 K 歌主功能。

参考机制：

- `跳一跳`：短局、单按钮、节奏判断、不服再来。
- 箭头/手速榜：视觉反应、极短挑战、排行榜。
- 轻关卡挑战：同一关卡 seed 可分享给朋友。

## 3. 目标

验证用户是否愿意：

1. 在手机点歌 H5 里点击一个切歌梗小游戏入口。
2. 5 秒内理解“亮区点击”和“点错惩罚”。
3. 完成 30 秒以上反应挑战。
4. 失败或低分后再来一局。
5. 生成结果图或挑战链接发给朋友。

## 4. 非目标

MVP 不做：

- 真实音乐播放和版权曲库。
- 音频节拍识别。
- 录唱、练歌、唱功评分。
- 多人实时对战。
- 完整 App。
- 付费系统。
- 门店真实排行榜。
- 商户券、附近推荐、组局履约。

## 5. 目标用户

### 核心用户

KTV 包厢内使用手机点歌 H5 的年轻用户，18-25 岁为主，男女混合。

典型场景：

- 等朋友唱歌时。
- 点歌间隙。
- 包厢气氛热起来后。
- 有人拿遥控器切歌、抢副歌、手滑时。

### 外延用户

- 同事局、生日局、同学局、中年朋友局。
- 分享链接进入的群友。

## 6. 核心假设

### 假设 1：切歌是混合人群都能理解的 KTV 梗

用户不需要懂音乐游戏，只要经历过 KTV，就能理解“副歌来了别切”“神曲别手滑”“冷场要救”的情境。

### 假设 2：短局反应挑战能激发不服再来

如果失误反馈足够明确，例如早切、晚切、手滑、冷场值爆表，用户会觉得自己能改进，愿意再来一局。

### 假设 3：结果图能变成群聊挑衅

高分、低分、手滑次数、冷场评级都适合发群，引导朋友挑战同一局。

## 7. 最核心的 3 个功能

### 功能 1：30 秒切歌反应局

#### 目标

让用户 5 秒理解玩法，30 秒完成一局。

#### 基础规则

- 游戏区展示一条“副歌轨道”。
- 事件卡从右向左滑动，进入判定区时需要点击按钮。
- 事件分 3 类，事件卡会直接标出该按哪个键：
  - `切`：前奏太长、社死歌等需要切掉。
  - `抢`：副歌来了、神曲别切等需要抢住。
  - `救`：冷场、朋友抢麦、遥控器漂移等需要救场。
- 点准得分并增加连击。
- 点早、点晚、点错扣分并增加手滑值。
- 冷场值满或时间结束后进入结果页。

#### MVP 事件类型

首版 8 类事件，全部由配置 JSON 驱动：

- 副歌来了
- 全员会唱
- 前奏太长
- 社死歌
- 冷场 3 秒
- 高音警告
- 朋友抢麦
- 遥控器漂移

#### 成功指标

- 入口点击率 >= 8%。
- 开局成功率 >= 70%。
- 首局 30 秒完赛率 >= 55%。
- 首局用户平均点击次数 >= 10。

#### 失败信号

- 用户 10 秒内退出 > 40%。
- 用户不知道该点哪个按钮。
- 完赛率 < 35%。

### 功能 2：手滑反馈与不服再来

#### 目标

让每一次失败都变得可解释，驱动再来。

#### 反馈类型

每局实时展示：

- 连击数。
- 准确率。
- 手滑值。
- 冷场值。

每次失误给 1 条短反馈：

- `早切 0.38 秒`
- `副歌到了你在犹豫`
- `手滑切掉全员会唱`
- `冷场值 +18`

结果页展示：

- 总分。
- 最大连击。
- 准确率。
- 手滑次数。
- 包厢评级。

#### 评级示例

- `遥控器不该交给你`
- `副歌守门员`
- `切歌急救员`
- `包厢节奏官`

#### 成功指标

- 失败后再来一局率 >= 25%。
- 结果页停留 >= 8 秒。
- 用户点击“再来”后的第二局完赛率 >= 50%。

#### 失败信号

- 用户觉得扣分随机。
- 用户不理解失败原因。
- 再来一局率 < 10%。

### 功能 3：同局挑战与结果海报

#### 目标

让结果成为群聊传播物。

#### 结果海报内容

- 标题：`切歌别手滑`
- 分数：`30 秒守住 13 个副歌`
- 评级：`包厢节奏官`
- 关键数据：
  - 准确率
  - 最大连击
  - 手滑次数
  - 冷场值
- 挑战文案：
  - `我 30 秒没切掉副歌，你来。`
  - `遥控器给你，你能撑几秒？`

#### 分享链路

- 用户点击分享结果。
- 生成结果图和挑战链接。
- 朋友打开后进入同一关卡 seed。
- 朋友完成后看到两人对比：
  - 分数更高或更低。
  - 谁手滑更多。
  - 谁冷场值更低。

#### 成功指标

- 结果图保存/复制文案/系统分享点击 >= 12%。
- 分享链接回流率 >= 5%。
- 同局挑战完成率 >= 30%。

#### 失败信号

- 用户只玩不看结果页。
- 分享点击 < 5%。
- 朋友打开后不知道要挑战什么。

## 8. 用户流程

### 首次进入

1. 手机点歌 H5 展示入口：`副歌快到了，别手滑`
2. 用户点击进入切歌别手滑。
3. 展示 2 秒玩法提示：
   - `等卡片进黄框`
   - `卡上写什么就按什么`
   - `手滑会涨冷场值`
4. 进入新手局。
5. 完成 30 秒挑战。
6. 展示结果页。
7. 引导再来一局或分享挑战。

### 分享回流

1. 用户收到挑战链接。
2. 首屏展示好友成绩。
3. CTA：`挑战同一段副歌`
4. 进入相同 seed 关卡。
5. 结果页对比两人表现。

## 9. 页面清单

| 页面 | 目的 | 关键组件 |
|---|---|---|
| 入口页 | 让用户点击开局 | KTV 控台视觉、30 秒挑战、开始按钮、好友成绩入口 |
| 选局页 | 让用户自己选强度 | 6 个固定局、简单/普通/困难/高压标签 |
| 玩法提示层 | 降低学习成本 | 3 条短提示、可跳过 |
| 游戏页 | 核心体验 | 副歌轨道、判定区、事件卡、操作按钮、连击、手滑值 |
| 失败/结算页 | 促使再来 | 分数、评级、失误原因、再来一局 |
| 结果海报页 | 传播 | 结果图、复制文案、同局挑战链接 |
| App 承接页 | fake-door | 每日挑战、好友榜、皮肤、赛季称号 |

### 选局页

首版采用轻量小游戏常见的 `一屏选择 + 难度标签 + 全部可玩`。

- 6 个固定局默认全部可点。
- 用 `简单`、`普通`、`困难`、`高压` 标出强度。
- 用户可自由换局，不做解锁和星级压力。
- 详细设计见 `product/level-system.md`。

## 10. 文案方向

### 入口文案

- 副歌快到了，别手滑
- 遥控器交给你 30 秒
- 看你是救场还是切掉神曲

### 实时反馈

- 早切了，副歌还没来
- 别切，这首全员会唱
- 冷场警报，快救一下
- 这一下像遥控器漂移

### 结果文案

- 遥控器不该交给你
- 包厢节奏官上线
- 副歌守住了，人也稳住了
- 你切掉了 2 首神曲，朋友正在沉默

### 分享文案

- 我 30 秒守住 13 个副歌，你来
- 遥控器给你，你能不手滑吗
- 这局真的不难，难的是别乱切

## 11. H5 与 App 分工

### H5 做

- 入口曝光。
- 6 个固定 seed 关卡。
- 自由选局和难度标签。
- 单局核心玩法。
- 手滑反馈。
- 结果海报。
- 同局挑战链接。
- App 承接 fake-door。

### App 承接

- 每日挑战。
- 更多节奏关卡。
- 好友挑战榜。
- 控台皮肤。
- 事件卡皮肤。
- 历史战绩。
- 赛季称号。

App 第一阶段不承接：

- 真实门店排行。
- 商户券。
- 本地生活。
- 陌生人广场。
- 复杂账号关系。
- 音频录制和评分。

## 13. MVP 成功阈值

| 指标 | 目标 |
|---|---:|
| 入口点击率 | >= 8% |
| 开局成功率 | >= 70% |
| 首局 30 秒完赛率 | >= 55% |
| 平均点击次数 | >= 10 |
| 失败后再来一局率 | >= 25% |
| 结果分享/保存/复制点击率 | >= 12% |
| 分享链接回流率 | >= 5% |
| App fake-door 点击率 | >= 3% |

## 14. 失败信号

- 入口点击率 < 3%：主题不吸引或入口位置不对。
- 首局 10 秒内退出 > 40%：规则不够直观或 UI 误导。
- 首局完赛率 < 35%：反馈或节奏设计失败。
- 失败后再来一局率 < 10%：不服循环没建立。
- 分享点击 < 5%：结果没有社交货币。
- 用户反馈“像音乐游戏但没有音乐”：需要强化这是切歌梗反应挑战，而不是真实节奏游戏。

## 15. 后续可复制皮肤

如果首版成立，同一套机制可换皮：

- 抢副歌挑战。
- 遥控器漂移挑战。
- 年会控场挑战。
- 直播间手速挑战。
- 群聊接梗反应挑战。
- 酒桌别手滑挑战。

每个皮肤只换事件卡、美术、文案和节奏配置，不改核心机制。

## 16. 首版交付建议

第一版做前后端分离 H5：

- 前端：Vite 静态 H5，读取关卡 JSON，完成核心交互。
- 后端：Node HTTP 服务，提供配置、上报事件、记录本地分数。
- 共享配置：`shared/game-config.json`。
- 结果海报：先用 Pencil 导出的静态背景 + DOM/Canvas 文本合成。
- 分享链接：用 URL seed 模拟同局挑战。

目标是在 Pencil 资产可用后 3-7 天内做出可现场试玩版本。
