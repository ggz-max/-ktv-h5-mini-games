# 搭子掼蛋

状态：可联机 MVP 已开发并部署 ThunderBox，版本 `0.2.0`。

公网地址：`https://ktv-guandan.tbox.ktvsky.com/`

这是 `包厢背锅王` 之后的下一款棋牌实验。它不再验证“多人同时选牌”，而是验证 KTV 熟人局中“固定搭档协作”能否形成更强的复玩和续局。

## 一句话玩法

四人两队、对家是搭档；使用两副牌，每人完整拿 27 张。打一把即可结算，主动再来一把时继承升级级数。

## 首版边界

- 完整保留成熟掼蛋的 2v2、两副牌、27 张手牌、逢人配、同花顺、多级炸弹、队友名次和升级。
- 轻量化只发生在赛程：首版打一把即结算，不要求连续升级到 A；单把目标 8～15 分钟。
- 4 名真人是标准有效局；1～3 人可用人机补位试玩，8 人可开两桌。5～7 人无法天然形成全员真人牌局，这是品类限制。
- 匿名扫码进入，不要求登录，不依赖员工讲解。
- 不做金币、筹码、押注、商城、长赛季和完整棋牌大厅。
- H5 承接进房、教学、完整一把、结算和续局；后续 App 只在实验通过后承接搭档战绩、级数进度和赛季荣誉。

## 当前已实现

- 两副牌 108 张洗牌发牌，四个座位每人 27 张。
- 单张、对子、三张、三带二、顺子、三连对、钢板、同花顺、4 张及以上炸弹、四王炸。
- 红桃级牌逢人配、多级炸弹比较、轮流出牌、不要、牌权重置和队友接风。
- 四人 WebSocket 联机、二维码/房间号加入、断线状态同步、房主迁移、超时托管和 1～3 真人的人机补位。
- ThunderBox 不支持当前 `/ws` 路由升级时，前端自动切换为 1 秒 HTTP 轮询和 HTTP action；创建、加入、开局、出牌均可继续使用。
- 失效房间 session 会自动清理并返回首页，断线恢复期间禁止静默提交操作。
- 人机会识别对家牌权、搭档剩牌和对手即将走完，在让牌、拦截和炸弹时显示战术反馈。
- 头游到末游名次、搭档名次升级、打一把结算、继续升级。
- 移动端 27 张可读手牌、合法牌提示、牌型预览和本地 Playwright 截图验收。
- 事件日志写入 `server/data/events.jsonl` 或 `DATA_DIR` 指定目录。

## 尚未实现

- 第二把开始前的进贡、还贡、抗贡流程。
- 从 2 连续打到 A 的完整比赛终局和过 A 判定。
- 8 人自动拆成两个独立真人牌桌。
- 生产级人机策略、陌生人匹配、账号、段位、商城和排行榜。

首版已经保住“大手牌、多组合、多级炸弹”的核心手感，但在加入进贡/还贡前，不应对外宣称完整复刻全部竞技赛制。

```powershell
npm run dev
```

## 与背锅王的差异

| 维度 | 包厢背锅王 | 搭子掼蛋 |
|---|---|---|
| 核心关系 | 所有人自由混战 | 固定对家搭档，2v2 |
| 操作节奏 | 全员同时选牌 | 轮流出牌，队友协作 |
| 乐趣来源 | 预判他人、挤爆背锅 | 喂牌、接风、炸弹与搭档带飞 |
| 实验假设 | 静音多人伴玩能否成立 | 固定搭档是否提高续局 |
| 首版人数 | 1～8 人同桌 | 标准 4 人一桌；8 人两桌，其他人数人机兜底 |
