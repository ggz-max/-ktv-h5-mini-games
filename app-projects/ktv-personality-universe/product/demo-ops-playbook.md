# KTV 人格宇宙 Demo 运营实验手册

## 1. 本轮只验证三件事

1. 用户愿不愿意测人格
2. 用户愿不愿意收集人格卡
3. 用户愿不愿意生成分享图

不要在现场解释太多概念，也不要把话题带到付费包、会员权益、在线 K 歌或复杂 App。先看最小闭环有没有爽感。

## 2. 本地启动

```bash
cd www-room-lineup
python -m http.server 5202 --bind 127.0.0.1
```

优先打开：

- 演示入口页：`http://127.0.0.1:5202/demo-launcher.html`
- 普通体验：`http://127.0.0.1:5202/?reset=1`
- 档案库状态：`http://127.0.0.1:5202/?reset=1&persona=ROMEO&owned=SPARK,ROMEO&bonus=2#library`
- 未解锁详情：`http://127.0.0.1:5202/?reset=1&owned=SPARK&detail=SKIP#library`
- 分享页：`http://127.0.0.1:5202/?reset=1#share`
- 运营漏斗：`http://127.0.0.1:5202/?ops=1#library`

参数说明：`bonus=2` 会在 `owned` 基础上额外解锁 2 张演示人格卡，用来快速预览档案库的收集状态。

## 3. 演示前检查

```bash
node tools/health-check.js
```

检查项包括 JS 语法、图片引用、关键 DOM、截图文件、风险词、乱码、三核心范围。

## 4. 推荐讲解顺序

1. 打开首屏，让对方先看标题和 4 个核心代码。
2. 直接点击开始测人格，由历史点唱画像生成第一张卡。
3. 到结果页后停一下，问“这个称号爽不爽、像不像 KTV 里的某类人”。
4. 点击“领取并入档案”，强调一键拿卡、装备、入库，不再连续确认。
5. 在领卡成功页让对方选择：看档案库、生成分享图或再测一次。
6. 进入档案库讲下一张目标和再测动机，再生成分享图问“愿不愿意发给朋友，让对方也测一下”。

## 5. 关键事件

| 事件 | 含义 | 看什么 |
| --- | --- | --- |
| `entry_view` | 进入首屏 | 入口是否能承接流量 |
| `scan_start` | 开始测人格 | 用户是否愿意测 |
| `result_view` | 看到结果 | 测试过程是否顺畅 |
| `reward_claim` | 领取并入档案 | 人格结果是否足够爽，卡片是否像资产 |
| `library_view` | 进入档案库 | 收集体系是否被理解 |
| `mission_action` | 点击下一步行动 | 是否能驱动再测或分享 |
| `share_create` | 进入分享图内容页 | 传播动机是否成立 |
| `poster_save` | 保存海报 | 分享图是否有价值 |
| `system_share` | 系统分享 | 原生分享是否可用 |
| `copy_share_text` | 复制文案 | 群传播是否有动作 |

## 6. 现场观察问题

- 用户是否能在 3 秒内理解这是一个 KTV 人格测试？
- 用户看到人格代码时有没有笑、吐槽、转头给朋友看？
- 用户是否理解“人格卡可以收集”？
- 档案库里的“下一张目标”是否让人想再测一次？
- 分享图是否适合发给朋友、群聊或朋友圈？
- 哪个按钮让用户犹豫？哪段文案让用户停住？

## 7. 判断标准

继续推进：
- 用户愿意主动点开始测人格
- 结果页有明显情绪反应
- 人格卡被理解为可收集资产
- 有人愿意保存或分享图

需要调整：
- 用户以为这是在线唱歌功能
- 用户看不懂人格卡和档案库关系
- 分享图不够想发
- 档案库看起来像普通列表，没有“下一张”的期待
