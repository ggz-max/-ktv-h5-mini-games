# KTV 人格宇宙体验审查 2026-06-26

审查目标：以产品体验官视角，围绕「炫酷、好玩、离开 KTV 也能用、可沉淀浏览、可分享」检查当前产品，并输出 Codex 可直接执行的优化建议。

## 状态修正：线上 H5 可以访问

用户浏览器截图已证明 `https://ktv-personality-universe.tbox.ktvsky.com/#entry` 能打开当前 H5 首页。此前用无登录态脚本直连时拿到 ThunderBox/Casdoor 壳页，只能说明脚本路径或登录态与真实用户浏览器不一致，不能作为「用户入口不可用」结论。

当前验收口径：

- `npm run verify:deployed` 只验证 H5 入口是否返回产品页面。
- 如需强制验证 `/api/health`，使用 `KTV_VERIFY_API=1 npm run verify:deployed`。
- 后续产品体验评审以真实浏览器可见 H5 为准，不再围绕部署阻塞打转。

每次部署后执行：

```bash
npm run verify:deployed
```

验收标准：

- `GET /` 包含 `KTV 人格宇宙`、`KTV 人格测试` 或 `data-view="entry"`。
- `GET /` 不包含 `Casdoor` 或 `<title>thunderbox</title>`。

## P1：首页需要一眼说明「这是干什么的」

当前首页方向已经比传统列表强，但仍要继续压缩认知成本。用户第一眼必须知道：

- 我是在测自己的 KTV 人格。
- 测完会得到一张可分享的人格卡。
- 朋友点开也能玩，不依赖包厢数据。

建议首页只保留 4 个核心信息：

1. 标题：`测出你的 KTV 人格`
2. 副标题：`30 秒生成可分享人格卡`
3. 视觉：一张强卡片预览，而不是多个入口解释。
4. CTA：`开始测人格`

删除或弱化：

- 过多模式按钮。
- 需要解释的内部词。
- 与唱歌功能强相关的误导文案，如「再唱一局」。

Codex 执行建议：

- 在 `www-room-lineup/index.html` 中保留 `entry-hero`、人格卡预览、主 CTA。
- 将入口文案统一为「人格卡」而不是「测一测」。
- 分享来源进入时显示好友卡片邀请，但不能抢走主 CTA。

## P1：测试链路应从多步确认改成连续拿卡

当前体验目标不是严肃测评，而是爽感和传播。链路应控制在 15 到 30 秒内：

1. 首页点开始。
2. 扫描 2 秒左右。
3. 立即开卡，并自动入档案。
4. 结果页给 `查看我的档案` 和 `生成分享图`。

Codex 执行建议：

- `showView("result")` 时自动 `ensureCurrentOwned()`。
- 结果页按钮从 `领取并入档案` 改为 `查看我的档案`。
- 次级按钮给 `生成分享图`。
- 扫描动画缩短，避免用户觉得在等假加载。

## P1：人格结果要有「被看穿」的刺痛感

现在卡片有视觉，但人格文案还要更像社交货币。用户愿意分享的不是「我拿到一张图」，而是「它把我说中了」。

每个人格需要稳定结构：

- 英文人格词：必须是真实单词，像 `ROMEO`、`LOOP`、`DROP` 这样一眼能读。
- 中文短名：3 到 5 个字，能直接懂。
- 一句狠话：带梗、带判断、带自嘲。
- 社交标签：适合被朋友评论。
- 反向弱点：轻微冒犯但不能伤人。

示例方向：

- `ROMEO 情歌脑`：你不是爱唱情歌，你是把每首歌都唱成未发送的消息。
- `DROP 副歌空投`：主歌你可以消失，副歌你必须降临。
- `LOOP 单曲循环体`：别人唱歌是娱乐，你唱歌像在修复某段人生。
- `SKIP 切歌脑`：你不是没耐心，你只是对无聊过敏。

Codex 执行建议：

- 在 `www-room-lineup/app.js` 的人格配置里增加 `verdict`、`weakness`、`shareHook` 字段。
- 结果页优先展示狠话和分享钩子，不要先展示长说明。

## P1：分享页要让被分享者立刻参与

当前分享如果只是展示我的结果，传播效率不够。被分享者需要一个明确动作：

- 先看到朋友的人格卡。
- 再看到一句挑衅式邀请。
- 一键生成自己的卡。
- 生成后能与朋友形成对比。

Codex 执行建议：

- 分享 URL 保留 `source=share&from=PERSONA_CODE`。
- 分享落地页首屏文案：
  - `朋友抽到了 ROMEO 情歌脑`
  - `你会是他的合唱搭子，还是切歌凶手？`
  - CTA：`测我的 KTV 人格`
- 结果页增加 `你和朋友的关系` 模块：
  - 合唱搭子
  - 互相切歌
  - 情歌事故现场
  - 热场双核

## P1：档案库要升级成个人主页

档案库不能只是列表或仓库。它应该像一个轻量主页，让用户愿意回来翻：

- 当前主人格。
- 已收集人格卡。
- 已解锁皮肤。
- 稀有度进度。
- 最近一次结果。
- 分享我的主页。

Codex 执行建议：

- 将 `library` 页面命名为 `我的人格档案` 或 `我的 KTV 人格宇宙`。
- 顶部展示当前装备卡。
- 中部展示卡册，不用传统列表，改成卡牌墙或横向橱窗。
- 底部给两个动作：`分享我的档案`、`再抽一张皮肤`。

## P2：离开 KTV 后的使用场景还不够

产品不能被包厢场景锁死。KTV 是获客入口，不是产品边界。

建议补充的场景语言：

- 聚会前：测一下今晚谁会控场。
- 聚会后：生成今晚人格卡。
- 朋友圈：晒人格卡让朋友对号入座。
- 通勤/车载：听歌人格也成立。
- 深夜 emo：情绪人格也成立。

Codex 执行建议：

- 替换所有过度依赖包厢的文案。
- 保留 KTV 氛围，但题目和结果扩展到「唱歌人格」「听歌人格」「朋友局人格」。

## P2：付费点应围绕炫耀，不要挡住核心结果

不要让用户为第一次结果付费。第一次必须免费爽到。

适合付费：

- 动态卡面。
- 稀有边框。
- 限定皮肤。
- 高清分享图。
- 好友兼容报告。
- 节日限定卡池。

Codex 执行建议：

- 结果页免费展示基础卡。
- 档案库展示锁定皮肤位。
- 付费入口文案用 `解锁动态皮肤`，不要用泛泛的 `开通会员`。

## P2：视觉资产工作流需要固定

本项目 UI 资产应遵循「Pencil 设计源文件 -> 导出运行时图片 -> H5 引用」。

资产源文件建议：

- `designs/pencil-source/pencil-welcome-desktop.pen`

运行时导出目录：

- `www-room-lineup/assets/visuals/`

规则：

- `.pen` 是设计源文件，负责管理多张图和分组。
- H5 不能直接读取 `.pen`，必须引用导出的 PNG/WebP。
- 新增 UI 图时先进入 `.pen`，再导出到运行时目录。
- 不再手写 JSON 假装 `.pen` 文件。

## 推荐下一轮改造顺序

1. 修线上部署，跑通 `node tools/verify-deployed-url.js`。
2. 首页重做成「人格卡产品」而不是「测试入口」。
3. 测试链路压缩为连续 3 到 5 题后自动开卡。
4. 结果页重写人格狠话和分享钩子。
5. 档案库改成个人主页和卡牌墙。
6. 分享落地页增加朋友卡对比。
