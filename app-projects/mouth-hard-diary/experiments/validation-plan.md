# 验证计划

## 验证目标

验证“嘴硬日记 / 发疯报告”是否值得进入 App 深做。

核心问题：

1. 用户是否会被入口吸引？
2. 用户是否愿意投入 30 秒生成？
3. 生成结果是否值得保存或分享？
4. 用户是否有二次生成/长期档案需求？
5. KTV 入口是否比普通社交入口更有效？

## 第一轮：H5 fake-door

周期：7 天。

执行清单见：

```text
experiments/pilot-runbook.md
```

入口：

1. 生成我的今日发疯报告。
2. 测测你今天是哪种嘴硬人格。
3. 把今天的破事翻译成朋友圈能发的话。

当前已配置为入口文案实验：

| variant | 入口标题 | 适合验证 |
|---|---|---|
| `report` | 把今天的破事，翻译成精神状态报告 | 报告/生成物心智 |
| `persona` | 测测你今天是哪种嘴硬人格 | 人格测试心智 |
| `translator` | 把今天的破事，翻译成朋友圈能发的话 | 表达工具/社交发布心智 |

可通过 URL 指定：

```text
/?variant=report
/?variant=persona
/?variant=translator
```

未指定时前端会随机分配并写入 sessionStorage。

来源参数也通过 URL 指定，用于区分 KTV、社群、自然分享回流：

```text
/?variant=report&source=ktv&campaign=after_song&channel=room_qr&storeId=store_001&roomId=room_009
/?variant=persona&source=social&campaign=seed_group&channel=wechat
/?variant=translator&source=shareback&campaign=poster&channel=friend_chat
```

展示位置：

- KTV 手机点歌结束页。
- 唱后歌单页。
- 普通二维码/社群投放页。

对照：

- KTV 来源。
- 非 KTV 社群来源。
- 朋友圈/群聊自然分享回流。

## 指标

| 阶段 | 指标 | 成功阈值 | 失败信号 |
|---|---|---:|---|
| 入口 | 点击率 | >= 10% | < 3% |
| 输入 | 完成率 | >= 50% | < 30% |
| 生成 | 成功率 | >= 85% | < 70% |
| 结果 | 保存率 | >= 20% | < 8% |
| 传播 | 分享率 | >= 12% | < 5% |
| 内容 | “太像我了”反馈占比 | >= 40% | < 15% |
| 风险 | “有点冒犯”反馈占比 | < 10% | > 20% |
| 复访 | 二次生成率 | >= 25% | < 10% |
| 承接 | App CTA 点击 | >= 5% | < 2% |
| 复玩 | 二次生成点击 | >= 25% | < 10% |

入口实验复盘：

- 在 `http://127.0.0.1:4327/admin.html` 查看“入口实验表现”。
- 先看“转化漏斗”，确认流失发生在入口点击、输入提交、生成成功、保存分享还是 App 承接。
- 在同一看板查看“来源表现”，先确认 KTV、社群、分享回流是否有明显差异。
- 在同一看板查看“App 兴趣”，确认用户更想要保存、日历、人格图鉴还是模板扩展。
- 在同一看板查看“留资意向”，确认微信提醒、手机号提醒和跳过之间的真实偏好。
- 在同一看板查看“内容反馈”，确认准、不准和冒犯反馈是否失衡。
- 点击“导出数据”下载 JSON，保留当日 `summary`、`reports`、`events` 原始明细。
- 点击“导出表格”下载事件计数、转化漏斗、入口实验、来源表现、App 兴趣、留资意向、内容反馈 CSV 文本表，用于日复盘。
- 运行 `npm run review:runtime` 生成 `docs/runtime-review.md`，沉淀当日结论和下一步建议。
- 对比 `report` / `persona` / `translator` 三组。
- 先看开始点击和报告生成，不急着用 App CTA 判死刑。
- 如果某组 `starts` 高但 `reports` 低，说明入口吸引但后续流程或预期不匹配。
- 如果某组 `reports` 低但 `saves` 高，说明人群窄但输出价值强，可考虑保留为二级入口。

正式投放前：

- 运行 `npm run sampling:links`，生成 `docs/sampling-links.md` 和 `docs/sampling-links.generated.json`。
- 运行 `npm run verify:sampling-links`，确认 `report`、`persona`、`translator` 和 KTV/社群/分享回流来源参数完整。
- 运行 `npm run sampling:prepare -- --yes`，备份并清空 `reports.jsonl`、`events.jsonl` 和 `interviews.jsonl`。
- 该命令会重新生成干净的 `docs/runtime-review.md`；若仍显示“含测试数据：是”，只把它当链路检查，不做真实转化结论。

## 第二轮：内容风格 A/B

变量：

- 体面崩溃 vs 抽象发疯。
- 温柔自救 vs 阴阳怪气。
- 称号型结果 vs 报告型结果。
- 单图海报 vs 文案复制。
- 入口心智：报告 vs 人格 vs 朋友圈翻译器。

判断：

- 保存率决定视觉产物。
- 分享率决定社交表达。
- “太像我了”决定内容命中感。
- “有点冒犯”决定安全边界是否需要收敛。
- 二次生成率决定是否做长期产品。

## 第三轮：App 承接假门

入口：

- 保存历史报告：`archive`。
- 精神状态日历：`calendar`。
- 嘴硬人格图鉴：`persona_atlas`。
- 更多发疯模板：`style_templates`。

成功阈值：

- 任一 App 承接点击率 >= 5%。
- 任一 App 兴趣项占兴趣点击 >= 40%，优先进入对应功能原型。
- 微信/手机号提醒意向率 >= 2%。

失败信号：

- 用户只愿意单次玩，不愿保存历史。
- 高分享但低留资，说明适合工具/小程序，不一定适合独立 App。
- `skip` 高于微信和手机号总和，说明承诺感过强，需要先做轻收藏或小程序入口。

## 访谈问题

生成后立即访谈 8-12 人：

1. 哪句话最像你？
2. 哪句话让你不想发？
3. 你会发给谁？
4. 你想保存它吗，为什么？
5. 明天你还会再测一次吗？
6. 如果有 App，你希望里面有什么？
7. 你不希望它做什么？

## 决策规则

进入 MVP 深做：

- 保存率 >= 20% 或分享率 >= 12%。
- App 承接点击 >= 5%。
- App 兴趣中出现明确第一名，且访谈能解释为什么需要它。
- 用户访谈中明确表达“想保存历史/想每天测/想换风格”。

降级为营销 H5：

- 点击率高，但二次生成和 App CTA 低。

放弃方向：

- 点击率、保存率、分享率都低。
- 用户认为内容尴尬、冒犯或无聊。
