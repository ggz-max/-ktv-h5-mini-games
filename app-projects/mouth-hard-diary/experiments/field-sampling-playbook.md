# 真实用户现场采样手册

目标：用 8-12 个真实年轻用户样本，验证“嘴硬日记 / 发疯报告”是否真的能成为情绪释放型产品，而不只是内部看起来有趣。

本手册用于正式采样当天执行。投放链接、门禁和指标判断见 `experiments/pilot-runbook.md`；本文只解决现场怎么找人、怎么观察、怎么问、怎么记录。

## 0. 开始前门禁

正式采样前必须完成：

```bash
npm run sampling:links
npm run sampling:prepare -- --yes
npm run verify:launch
```

如果 `verify:launch` 没过，只能做内部链路演练，不能把数据当成真实结论。

当前已知硬门禁：

- UI 图片必须先进入 Pencil `.pen`，经确认后从 Pencil 导出切图，H5 只引用导出图。
- runtime JSONL 必须在真实采样前清空，避免混入本地验证数据。
- 采样页必须展示匿名采样说明，不收真实手机号、微信或身份信息。

## 1. 招募样本

优先找 18-30 岁用户，尤其是 18-25 岁、熟悉自嘲梗、人格测试、情绪表达内容的人。

建议配额：

| 分组 | 人数 | 用途 |
|---|---:|---|
| 熟人种子用户 | 4-5 | 快速发现文案、生成结果和分享动机问题 |
| 陌生或半熟用户 | 3-4 | 验证冷启动吸引力 |
| KTV/聚会场景用户 | 2-3 | 验证情绪释放内容是否适合线下娱乐场景 |

不要只找“会夸的人”。至少保留 3 个表达直接、不怕说难听话的用户。

## 2. 现场口径

开场只说：

> 我们在测一个轻内容小工具，会把今天的烦事生成一张可保存的“精神状态报告”。过程大约 1 分钟，只记录匿名点击、生成结果和反馈，不收真实手机号、微信或身份信息。

不要提前解释产品愿景、App 规划或你期待用户分享。让用户自然完成。

如果用户问是不是心理测试：

> 不是心理诊断，也不做建议，只是娱乐表达和情绪出口。

## 3. 观察记录

用户操作时不要指导，除非页面真的卡住。观察以下行为：

| 阶段 | 观察点 | 记录方式 |
|---|---|---|
| 入口 | 是否愿意点开始，是否读懂“发疯报告” | 记录原话和停顿 |
| 选择 | 哪个场景或嘴硬方式最先吸引 | 记录选择项 |
| 输入 | 是否愿意补一句真实情况 | 只记录是否输入，不记录敏感原文 |
| 结果 | 是否笑、截图、复读某句话 | 记录具体反应 |
| 分享 | 是否想发群聊、朋友圈或私聊 | 记录分享对象 |
| App 假门 | 点了哪个 App 能力，是否愿意留提醒 | 记录选择和理由 |

原始输入不要复制进复盘文档。只保留概括，例如“工作压力”“失恋后嘴硬”“怀旧情绪”。

## 4. 访谈问题

生成后立刻问，控制在 3-5 分钟：

1. 哪一句最像你？
2. 哪一句让你不想发出去？
3. 你会把这张图发给谁？为什么是这个人或群？
4. 你会保存它吗？保存之后什么时候会再看？
5. 明天你还会再测一次吗？需要什么理由？
6. 如果它做成 App，你最想要哪一个功能：历史报告、状态日历、嘴硬人格图鉴、更多发疯模板？
7. 它最不该做什么？

追问只围绕真实行为，不争辩用户判断。

## 5. 后台录入

每完成 1 个用户，当场打开：

```text
http://127.0.0.1:4327/admin.html
```

在“访谈记录”里录入：

- 用户分组：`seed` / `cold` / `ktv`
- 来源：对应采样链接的 `source`
- 关键原话：只写 1-3 句，不写身份信息
- 是否保存、是否分享、是否想复玩
- 对 App 功能的真实偏好
- 风险信号：尴尬、冒犯、像广告、太像心理诊断

当晚运行：

```bash
npm run review:runtime
npm run brief:founder
```

## 6. 当晚复盘

先看行为数据，再看访谈：

1. `report` / `persona` / `translator` 哪个入口完成率最高？
2. 保存率和分享率是否至少有一个接近阈值？
3. “太像我了”是否来自具体句子，而不是礼貌性反馈？
4. “有点冒犯”是否集中在某种风格或某类场景？
5. App 兴趣第一名是否能被访谈解释？
6. KTV 场景是否真的强于社群种子，还是只是内部想象？

当晚只做一个决策：

| 结论 | 条件 |
|---|---|
| 继续采样 | 指标不够但用户能说出明确喜欢或不喜欢原因 |
| 进入 MVP 深做 | 保存、分享、App 兴趣至少两项成立，且访谈有复玩理由 |
| 只做传播 H5 | 分享强，但 App 兴趣和复玩弱 |
| 暂停方向 | 点击、保存、分享、访谈命中感都弱 |

## 7. 现场异常

如果用户觉得内容冒犯：

- 不解释、不辩护，记录是哪句话、哪种风格。
- 引导用户点“不舒服/有点冒犯”反馈。
- 当晚复盘时优先收紧对应文案模板。

如果用户以为在做心理诊断：

- 说明这是娱乐表达，不是诊断或建议。
- 记录是入口、结果页还是视觉风格造成了误解。

如果用户愿意留联系方式：

- 当前 MVP 不收真实手机号或微信。
- 只记录“愿意微信提醒 / 愿意手机号提醒 / 先不用”的选择意向。
