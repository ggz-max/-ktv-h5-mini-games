# 内容系统：发疯报告文案库

## 为什么要做内容库

嘴硬日记的核心不是“生成一段文本”，而是稳定产出让用户觉得“说中了、好笑、能发”的表达物。

因此文案必须像产品资产一样管理：

- 可运营新增。
- 可 A/B 测试。
- 可下线风险内容。
- 可按场景和风格组合。
- 可逐步积累爆款句式。

## 当前内容源

服务端内容文件：

```text
server/data/report-content.json
```

包含：

- `scenes`：破事类型、场景标题、场景解释。
- `styles`：嘴硬风格、主文案池。
- `advice`：今日建议。
- `crisis`：高风险输入兜底文案。
- `riskWords`：第一版高风险关键词。

## 生成逻辑

输入：

- `scene`：今天主要破事。
- `style`：嘴硬风格。
- `text`：用户可选短输入。

输出：

- 今日称号：从 `scenes[scene].titles` 选择。
- 主文案：从 `styles[style].quotes` 选择。
- 三条解释：从 `scenes[scene].bullets` 选择。
- 今日建议：从 `advice` 选择。
- 能量条：由 seed 生成，保证有轻随机感。

## 内容原则

- 好笑，但不羞辱用户。
- 毒舌，但不攻击具体第三方。
- 嘴硬，但不否认真实痛苦。
- 抽象，但用户能一眼看懂。
- 不做心理诊断，不承诺疗愈。
- 危机兜底必须去玩笑化，明确提示可信的人、紧急服务或专业热线。

## 好句标准

一条合格主文案应该满足：

1. 20-40 字。
2. 能截图转发。
3. 有轻微刺痛感。
4. 不需要上下文也能懂。
5. 不包含医疗化判断。

例：

> 你不是没事，你只是把崩溃调成了静音模式。

## 运营机制

每周新增：

- 每个 scene 至少 3 个 title。
- 每个 style 至少 5 条 quote。
- 每周复盘保存率和分享率最高的 20 条。

下线机制：

- 被用户反馈冒犯。
- 引发误解为诊断。
- 鼓励报复、自伤、危险行为。
- 过于阴暗或让人不适。

## 发布前检查

运营改内容库后运行：

```bash
npm run verify:content
npm run verify:copy
```

`verify:content` 检查结构、字段和长度；`verify:copy` 检查重复、医疗化/攻击性禁词、危机兜底安全提示和去玩笑化边界。
